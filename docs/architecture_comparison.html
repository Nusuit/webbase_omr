1. Hai pipeline từ ảnh đến kết quả

Không dùng một flow "CV hoặc YOLO" chung nữa. Codebase hiện có hai pipeline cần phân tích riêng: CV-only dùng xử lý ảnh truyền thống để localize sheet; Hybrid dùng YOLO để localize trước, sau đó vẫn dùng CV/OMR core để đọc bubble. Web và Native đều được đặt lên cùng stage để thấy stage nào đang lệch thời gian.

không chạy model

2. Pipeline CV-only: user input -> CV -> OMR result

Pipeline này áp dụng cho Web CV và Native CV. Không có YOLO ở bất kỳ stage nào. Preview dùng cùng một raw sheet để minh họa từng bước xử lý ảnh; timing là mean/p95 từ batch N=179. Với Web, các stage bên trong OMR core hiện chưa export riêng nên được ghi rõ là nằm trong cpp_ms. 3. Pipeline Hybrid: user input -> YOLO localization -> CV/OMR result

Pipeline này áp dụng cho Web YOLO raw và Native YOLO NNAPI. Điểm quan trọng: YOLO chỉ làm localization/handoff. Phần đọc MSSV, mã đề và đáp án vẫn là CV/OMR core phía sau, nên preview sau YOLO sẽ quay lại các stage marker crop, threshold và density. 6. CV-only vs Hybrid: khác nhau ở đâu?

Phần dùng chung sau localization

Canonical canvas1700x2400 là hệ tọa độ cố định cho mọi block.
Stage 2 marker cropLuôn tìm lại registration squares để sửa residual perspective.
Bubble sampling300 bubble centers, radius R=18, circular density.
Decision rulePer-row z-score + floor 0.15 cho answers; density threshold cho MSSV/KEY.
Khía cạnh CV YOLO
Vai trò Localization bằng xử lý ảnh truyền thống: marker corners trước, paper boundary fallback. Localization bằng detector học máy; nhận vùng marker/paper để mask hoặc crop trước khi vào OMR core.
Recognition Không phải YOLO. Câu trả lời vẫn được đọc bằng threshold + density + z-score trong OMR core.
Khi nào lợi Ảnh đủ rõ marker, nền không gây nhiễu mạnh; không tốn model inference. Ảnh có nền phức tạp hoặc cần loại bỏ background trước khi corner detection.
Rủi ro hiện tại Corner detection có thể chọn nhầm marker khi nền tối hoặc marker yếu. Nếu mask/crop sai, Stage 2 và grid anchor lệch; artifact raw dùng YOLO để đo nhưng không cho YOLO can thiệp recognition.
Runtime cost Không có model inference; bottleneck là WASM/OpenCV/C++ hoặc OpenCV ARM. Thêm 158-329 ms inference tùy provider, cộng thêm C++/OpenCV OMR phía sau.

Bottleneck chính là OMR compute trên Web

Redmi Web CV dùng 524.2 ms cho C++/WASM, trong khi Native CV dùng 87.6 ms cho phần tương ứng. Đây là nguồn gap lớn nhất.

YOLO không thay thế bubble reading

YOLO chỉ định vị vùng giấy/marker. Nếu muốn YOLO cải thiện accuracy, phải chứng minh output localization làm thay đổi kết quả sau C++.

SIMD/threads là hướng tối ưu Web

Worker có logic chọn omr_threads/omr_simd, nhưng nếu file chưa build thì fallback omr.wasm. Đây là optimization target rõ nhất.

8. Code paths và artifact dùng cho trang này

Web runtime

  • web/js/worker-cv.js: decode, RGBA extraction, raw handoff, perf fields.
  • web/js/worker-yolo.js: WebGPU/WASM ORT, 640 letterbox, marker_corners detection, mask/raw handoff.
  • web/js/wasm-bridge.js: JS bridge into exported C++ OMR functions.

C++ OMR core

  • src/core/omr_warp.cpp: downscale, grayscale, marker corners, paper fallback, homography, warp.
  • src/core/omr_core.cpp: Stage 2 crop, adaptive threshold, fixed grid, density sampling, z-score decode.
  • scripts/build_opencv_variants.sh: intended path for SIMD/threaded WASM variants.

Native Android

  • android/app/src/main/java/.../OmrProcessor.kt: orchestration, cropByMarkers, threshold, bubble reading.
  • android/app/src/main/java/.../PaperDetector.kt: Stage 1 detector contract.
  • android/app/src/yolo/java/.../YoloPaperDetector.kt: ORT Android CPU/CPU4T/NNAPI provider logic.

Benchmark artifacts

  • runs/batch_results/redmi_note13_pro_plus_cv_e2e_n179.json: Web CV E2E stage timings.
  • runs/batch_results/redmi_note13_pro_plus_native_cv_n179.json: Native CV same-device baseline.
  • runs/batch_results/redmi_note13_pro_plus_yolo_raw_n179.json và native YOLO provider JSONs.
Đọc số liệu: Web CV E2E có đủ jpeg_decode_ms, rgba_extract_ms, cpp_ms. Web YOLO raw hiện thiếu decode/RGBA trong JSON nên chỉ so sánh như worker-boundary. Native Android source build đầy đủ nằm ở sibling project theo android/README.md; thư mục này có snapshot đủ để trace pipeline chính.
