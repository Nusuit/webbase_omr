Phát hiện chính & hướng tối ưu

  • Web CV đang chạy WASM baseline. Worker chọn omr_threads (SIMD+đa luồng, server đã bật COOP/COEP) nhưng omr_simd.wasm/omr_threads.wasm chưa build → importScripts 404 → fallback omr.wasm. Tức 524 ms cpp đơn luồng, phí 8 nhân Redmi.
  • Lever lớn nhất: build omr_threads (SIMD128 + pthreads). Kỳ vọng cpp 2-6× nhanh hơn → E2E 708 → ~250-400 ms → tỉ lệ Web/Native 6.66× xuống ~2-3×. Infra build đã có (scripts/build_opencv_variants.sh), cần Emscripten.
  • Lever phụ: giảm canonical resolution (warp 1700×2400 = 4M px → nhỏ hơn) — tuyến tính theo pixel, nhưng phải test accuracy.
  • Boundary đã sửa: trước đây Web đo cpp_ms (worker compute) còn Native đo e2e_ms (file-based) — lệch. Nay cả hai đo cùng boundary decode→answers, ratio 6.66× là so sánh công bằng same-device.
  • Recognition đã parity trên ảnh đủ sáng (Web ~99%, Native 99.6%). Native 87% tổng bị kéo bởi 25 ảnh nền tối (corner detection chọn nhầm marker) — vấn đề localization riêng, không phải đọc bubble.
  • Caveat đo: Native = debug build (release nhanh hơn). YOLO E2E chưa đo (Native YOLO pipeline còn cần fix raw-handoff trước).
